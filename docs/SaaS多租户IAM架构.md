# SaaSGuard IAM：SaaS 多租户 IAM 架构

## 1. 目标

SaaSGuard IAM 是独立身份域，不属于 ERP 或 MES。它面向多个租户和多个业务应用，提供统一人员事实源、应用访问入口、协议令牌和审计；业务权限仍归各子系统。

## 2. 权限层级

| 主体 | 管理范围 |
|---|---|
| 平台超级管理员 | 创建/停用租户、套餐与配额、跨租户运维 |
| 租户管理员 | 本租户用户、组织、应用、授权和审计 |
| 应用管理员 | 委托应用内的人员启停、角色标签和同步（演进目标） |
| 普通员工 | 登录已分配应用、查看自己的授权 |
| 服务账号 | 仅以 Client Credentials 调用指定租户的同步 API |

平台超级管理员通过 `X-Tenant-Id` 显式切换数据视角；其他主体始终锁定令牌中的租户，不接受请求头越权切换。

## 3. 数据隔离

- `iam_tenant` 是平台共享目录；
- 人员、组织、应用、应用分配、应用角色、生命周期与审计表按 `tenant_id` 隔离；
- MyBatis-Plus 租户拦截器自动追加租户条件和插入字段；
- 共享表必须进入显式白名单，拿不准的数据默认隔离；
- 异步任务、事件监听器和服务令牌必须在提交前捕获租户 ID，并在工作线程恢复上下文；
- 集成测试至少使用 `demo(1000)` 与 `acme-demo(2000)` 两个租户验证正向访问和反向不可见。

## 4. 租户初始化

创建租户是一个事务：

1. 写入租户目录与品牌/套餐/配额；
2. 发布租户创建事件；
3. 在目标租户上下文创建根组织；
4. 创建首位租户管理员；
5. 分配 `TENANT_ADMIN`；
6. 写入生命周期事件。

任一步失败都会回滚，避免出现“租户有目录但不能登录”的半初始化状态。

## 5. OIDC 租户边界

- 授权登录从 `tenant_code` 定位租户；
- 管理登录令牌携带 `tenantId`；
- 授权码保存 `tenantId`，兑换时必须与请求租户一致；
- Client ID 及密钥在租户内查询，同名 Client 可存在于不同租户；
- Access Token、ID Token、Service Token 都带 `tenantId`；
- Service API 过滤器验签后恢复租户上下文；
- PKCE 仅允许 S256；RS256 令牌包含 `kid`、`iss`、`aud`、`iat`、`exp` 与 `jti`。

## 6. 身份同步

人员与授权变更在数据库事务提交后异步发布同步事件，避免子系统收到最终会回滚的数据，也避免下游故障阻塞主事务。事件显式携带 `tenantId`，应用按注册配置接收对账通知，并可使用服务令牌调用对应租户的全量/增量接口。服务令牌具备 Redis 在线态，应用停用或密钥重置后立即失效。后续将补充标准 Webhook Outbox、重试退避、死信与 SCIM 2.0 端点。

## 7. 安全演进

当前版本适合本地演示和持续产品化开发。进入生产前应补齐 Spring Authorization Server、MFA/Passkey、会话与设备中心、密钥轮换、授权同意记录、限流锁定、风险策略和安全运营告警。路线图能力未实现前，不在文档或发布说明中声称完整合规认证。

## 8. 开源边界

开源仓库只包含通用领域模型、公开依赖和虚构演示数据。禁止复制真实项目中的客户标识、员工数据、域名/IP、私有依赖地址、证书、私钥、生产账号或环境配置。参考既有系统时仅做行为级 clean-room 实现。
