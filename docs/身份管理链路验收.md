# 身份管理链路与验收

本期面向单企业／单集团部署。后台保持默认租户 1000，不展示租户选择，不把组织节点等同于 SaaS 客户。独立客户隔离、租户管理员和租户登录识别属于后续工作。

## 组织和编号

| 类型 | 新建编码示例 | 允许的下级 |
| --- | --- | --- |
| 集团 GROUP | GRP-000001 | 公司、工厂、部门、车间、班组、其他 |
| 公司 COMPANY | CO-000001 | 工厂、部门、车间、班组、其他 |
| 工厂 FACTORY | FAC-000001 | 部门、车间、班组、其他 |
| 部门 DEPARTMENT | DEPT-000001 | 部门、车间、班组、其他 |
| 车间 WORKSHOP | WS-000001 | 班组 |
| 班组 TEAM | TEAM-000001 | 无 |
| 其他／待分类 OTHER | ORG-000001 | 除集团外的组织，用于历史兼容 |

根组织允许集团、公司、工厂及历史兼容的其他类型；部门、车间、班组必须挂靠上级。

编号由数据库持久化流水生成，按默认租户＋前缀分别递增，六位是最小补零宽度，不会在超过六位时截断。员工编号为 EMP-000001，同时作为默认登录名。流水与建档共享事务，并发建档不会重复编号，已删除记录的编码也不复用。

历史编码不批量改写。迁移只把历史根组织标为集团，其他历史组织标为“其他／待分类”，需按实际含义确认。编码在创建时反映类型；后续改类型、改名称或换上级均保持编码不变，关系以 parent_id 为准。

后端拒绝自己挂到自己或后代下面、无效类型、停用上级和不兼容的上下级类型。停用组织前必须转走未离职员工，并停用启用中的下级；删除组织要求没有子组织、没有任何员工档案（含离职档案）。

## 员工与应用流程

1. 创建员工：姓名、组织、初始密码、岗位、入职日期与联系方式；工号无需填写。入职日期使用日期组件，不能晚于今天。初始密码按本期需求为 6–64 位。
2. 创建成功：展示工号／登录名，直接进入分配应用；可以稍后再分配。创建和分配是两个明确步骤，分配失败不会重新创建员工。跨应用部分成功时保留成功结果，提示剩余应用重试。
3. 分配：可从员工“分配应用”或应用“分配用户”进入；只允许在职用户。重复分配幂等，移除后可以重新分配，原管理员角色不会自动恢复。
4. 应用访问：停用访问保留分配和角色，恢复时需重新登录；移除用户取消本应用分配及角色，不删除员工档案。角色在单独弹框中保存。
5. 修改档案不要求密码；组织变动通过转岗办理。转岗保留工号、记录前后组织，并撤销中心原会话，重新登录获得新组织信息。
6. 全局停用可恢复；离职不可恢复。离职、全局停用及重置密码撤销该员工在认证中心登记的管理端与 OIDC 会话。管理员不能停用或离职自己。
7. 变更记录保留建档、档案修改、转岗、状态变化、离职及重置密码事件。界面展示最近 100 条；不记录密码内容。

应用端的用户同步返回 `active=false` 以及 `REVOKED`、`LEFT`、`SUSPENDED`、`APP_DISABLED` 等原因。增量查询覆盖员工、组织和应用分配的更新时间，包含时间边界，消费端应按工号幂等处理。

## 验证范围与边界

`IdentityChainIntegrationTest` 使用独立新建 MySQL 数据库和独立 Redis，通过真实 Spring Security HTTP 过滤器、MyBatis、Flyway 和 OIDC 授权码＋PKCE 验证：

- 组织类型、不同前缀、重新挂靠不变码、环检测、删除约束。
- 员工建档、自动登录名、无密码修改档案、未分配拒绝授权。
- 分配、重复分配、角色移除后重新授予、应用停用／恢复、移除后重新分配。
- OIDC 登录、令牌签发、旧令牌撤销；已签发授权码不能在员工停用后换令牌。
- 转岗不变工号、全局停用／恢复、重置密码、离职终态及事件记录。
- 移除、离职在同步接口中的失效结果。
- 并发 8 个员工编号唯一、密码长度、入职日期、停用组织及自停用限制。

仅离线验证 JWT 签名的业务系统无法即时感知中心撤销。ERP/MES 自己签发的本地会话，需要按同步结果注销、在线校验或接入登出通知；本次不把“中心令牌已失效”等同于“所有业务系统本地会话已立即下线”。部署后，旧版本未登记在线态的 OIDC 令牌需要重新登录。

## 重跑

需要 Java 21、本地 auth-mysql（13306）与一个专用于测试的 Redis。测试类只有 `AUTH_CHAIN_TESTS=true` 时运行；它会自动创建随机前缀 `auth_chain_test_` 数据库，并在结束时删除该库，不使用 auth_db 中的员工和组织。

```bash
# 创建临时 Redis，docker port 命令显示随机映射的测试端口
docker run --rm -d --name auth-chain-verify-redis -p 127.0.0.1::6379 redis:7-alpine redis-server --requirepass chain-test-only
docker port auth-chain-verify-redis 6379

# 在 auth-backend 目录，将测试端口替换为上一条输出的实际端口
AUTH_CHAIN_TESTS=true AUTH_TEST_REDIS_PORT=测试端口 mvn package

# 测试结束，仅关闭这次创建的测试容器
docker stop auth-chain-verify-redis

# 在 auth-web 目录
pnpm build
```

运行测试需要本地 MySQL 管理账号；开发密码默认沿用开发配置，也可通过 AUTH_TEST_MYSQL_PASSWORD 覆盖。中断导致的残留测试库应核对完整名称后单独清理。
