# 统一认证中心设计文档

> 对标：微软 Entra ID 应用模型 + 国内 4A 平台（账号/认证/授权/审计）+ OpenID Connect Core 1.0 / RFC 6749。
> 分期计划与环境事实见 ../AGENTS.md 与 开发进度.md。

## 1. "物业门禁"职责模型

认证中心 = 集团写字楼物业：

| 比喻 | 职责 | 落地 |
|------|------|------|
| 人 | 主账号生命周期（入职建号/转岗/离职/全局停用） | `idm_user` + 状态机，全部收口在中心 |
| 门 | 应用注册与进门权分配 | `app_client` / `app_user_assign` |
| 店长 | 系统管理员标签（`xxx.admin`） | `app_client_role` / `app_user_role` |

各业务系统（ERP/MES）自己管店内角色→菜单/按钮/数据权限；**认证中心永远不存业务系统的菜单**。

## 2. 主账号生命周期状态机

```
             入职建号
                │
                ▼
   ┌───────── 在职(1) ─────────┐
   │  转岗(留痕)   │             │
   │              ▼             ▼
全局停用(3)◀─停用/恢复─      离职(2，终态)
   │                            │
   └────── 可恢复在职 ──┐        │
                      ▼        ▼
            一切应用级操作被拒绝（离职为最强状态）
```

- 匹配/关联属性用**不可变工号**（employee_no，SCIM externalId 思路），不用邮箱；
- 离职/全局停用时**删除该用户全部 Redis 在线会话键**（`token:{userId}:*`），实现"一键全系统失效"（令牌侧）；
- 登录名默认同工号；登录支持登录名或工号。

## 3. 应用模型与角色

- `app_client`：client_id / 密钥(BCrypt) / redirect_uri（精确匹配）/ access_token 有效期 / consent_required / 启停状态 / 应用管理员（委托预留）；
- `app_client_role`：应用声明的角色标签（本期即 `xxx.admin`）；
- `app_user_assign`：用户×应用进门权 + **应用级状态**（启用/禁用，业务系统管理端经服务间 API 调整，仅影响本应用）；
- `app_user_role`：用户×应用×角色标签（本期即管理员标签）。

**升级路径**（本期不实现）：应用注册时声明完整角色清单 → 中心分配普通角色 → token roles claim 自动携带，协议与表结构无需变更。

## 4. OIDC 协议（授权码 + PKCE）

端点（issuer = `http://localhost:8082/api`，可配 `auth.oidc.issuer`）：

| 端点 | 说明 |
|------|------|
| `GET /.well-known/openid-configuration` | 发现文档 |
| `GET /.well-known/jwks.json` | RS256 验签公钥（kid 轮换预留） |
| `POST /oauth/authorize` | 授权确认（统一登录页登录后调用，返回带 code/state 的回调地址） |
| `POST /oauth/token` | 授权码+PKCE 换 access/id token；`client_credentials` 换服务间令牌 |
| `GET /oauth/userinfo` | 用户信息（RS256 access token） |
| `POST /oauth/logout` | 单点登出（jti 拉黑） |

流程（SPA 统一登录页版，对业务系统与标准重定向流一致）：

```
业务系统 ──浏览器重定向──▶ 认证中心前端 /oauth/authorize?client_id=...&redirect_uri=...
                              │ 未登录→统一登录表单（loginType=OIDC，登录日志留痕）
                              │ consent_required=1 → 授权确认页
                              ▼
                        POST /api/oauth/authorize（带管理端 JWT）
                              │ 校验：应用启用/redirect_uri 精确匹配/用户在职且已分配且应用级启用
                              ▼
                        一次性授权码（Redis 60s，绑定 PKCE challenge）
                              │ 浏览器跳回 redirect_uri?code=..&state=..
                              ▼
业务系统后端 ──POST /oauth/token（Basic + code + code_verifier）──▶ access_token(RS256) + id_token
```

access token claims：`sub`(userId)、`aud`(client_id)、`iss`、`roles`（仅该应用角色标签）、
`employee_no`、`org_id`、`tenant_id`、`name`、`username`、`scope`。ABAC 预留：组织等属性独立 claim。

单点登出：本期实现令牌侧（jti 拉黑 + userinfo 失效）；front/back-channel 广播为业务系统按需对接项。

**本地降级账号策略（已拍板保留）**：ERP/MES 各保留一个本地超管账号（套件统一规范：
`erp_admin`/`mes_admin`，密码 123456），定位为"中心不可用时的破窗账号"，不属于主账号体系、
不参与 SSO、生命周期不受中心管控。约束：仅紧急使用（SSO 正常时不应日常使用）；
凭证永不下沉——中心同步给业务系统的用户副本只含授权信息（工号/组织/active/角色），
不含密码哈希；中心宕机时已登录会话靠本地 JWKS 缓存验签继续可用，新登录靠本地降级账号应急。

## 5. 服务间 API（业务系统后端 ↔ 中心）

认证：`POST /oauth/token`（grant_type=client_credentials，Basic 应用凭证）→ RS256 service token（scope=service）。

| 接口 | 说明 |
|------|------|
| `GET /service/apps/{clientId}/users?updatedSince=` | 用户增量/全量同步（SCIM 风格对账：`active=false` + inactiveReason=LEFT/SUSPENDED/APP_DISABLED） |
| `PUT /service/apps/{clientId}/users/{employeeNo}/status` | 应用级启停（body `{"enabled":false}`） |

约束：service token 的 client_id 必须与路径一致（应用只能操作自己的用户）；
应用级启停**仅对在职员工**可操作（离职/全局停用返回业务异常）。

## 6. 两套令牌体系（勿混用）

| 体系 | 用途 | 算法 | 密钥 | 失效机制 |
|------|------|------|------|----------|
| 管理端 JWT（JwtTokenProvider，HS256） | 认证中心管理端 + 统一登录页登录态 | HS256 | auth.jwt.secret | Redis 在线键 + 黑名单 |
| OIDC 令牌（OidcTokenService，RS256） | 业务系统 access/id/service token | RS256 | token_key 表（JWKS 发布） | 登出 jti 拉黑 + 离职清会话键 |

## 7. 审计（4A 第一层）

- **登录日志** `audit_login_log`：管理端 + OIDC 登录的全部尝试（成功/失败原因/IP/UA/类型/应用），异步落库；
- **操作日志** `audit_op_log`：管理端全部写操作（POST/PUT/DELETE）经 OpLogFilter 统一切面落库（敏感字段脱敏、截断 512）；
- **生命周期事件** `idm_user_event`：建号/转岗/离职/状态变更/重置口令留痕。

查询接口 `/audit/login-logs`、`/audit/op-logs`：SUPER_ADMIN 与 AUDITOR 可读。

## 8. 认证中心自身 RBAC

平台角色（V11 种子）：SUPER_ADMIN（全权）、APP_ADMIN（预留：应用管理员委托视图，app_client.admin_user_id）、AUDITOR（只读审计）。

## 9. 租户模型

预留租户维度：全表含 tenant_id（默认 1000），TenantLineInnerInterceptor 自动过滤；
共享表白名单见 `TenantConfig.TENANT_SHARED_TABLES`（sys_role/app_client/app_client_role/token_key 等）。
