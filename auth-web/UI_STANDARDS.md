# SaaSGuard IAM 前端 UI 基线

本项目以 Ant Design 为组件基座，遵循 WCAG 2.2 AA 的基础可访问性要求。新增页面和组件必须符合以下规则，不在业务页面重复发明布局和交互方式。

## 0. 强制使用的基础设施

- Ant Design 主题令牌只在 `src/theme/index.ts` 定义，CSS 专用语义变量只在 `src/styles/global.css` 的 `:root` 定义；业务页面禁止新增十六进制颜色。
- 页面标题使用 `PageHeader`，服务端分页列表使用 `PageTable`，筛选区使用 `FilterBar`，业务状态使用 `StatusTag`。
- 业务弹框使用 `StandardModal`，侧边任务面板使用 `StandardDrawer`；业务页面禁止直接导入 Ant Design 的 `Modal` 和 `Drawer`。
- 超过 7 个字段的表单使用 `FormSection` 分组；页面样式优先使用全局语义类，禁止重复编写布局型内联样式。

## 1. 页面与滚动

- 管理端应用壳固定为 `100dvh`，浏览器文档本身不承担业务内容滚动。
- 页面级容器、分栏、Modal 和 Drawer 优先使用 `%`、`vw`、`dvh`、`clamp()`；同时设置合理的最小/最大值，禁止只写一个固定宽高覆盖所有屏幕。
- 图标、边框、控件高度和最小可点击区域可使用固定尺寸，避免随屏幕比例缩放后失真或不可操作。
- 页面内容只在 `.admin-content` 中滚动；表格列超宽时在表格容器内横向滚动。
- 一个区域只保留一个主要纵向滚动容器，避免页面、卡片、表格同时出现嵌套滚动条。

## 2. Modal 与 Drawer

- Modal 最大高度以 `94dvh` 为主，同时受 900px 上限和实际安全边距约束；窄屏使用 `min(96dvh, 100dvh - 24px)`。
- Modal 标题和底部操作区固定，只有 `.ant-modal-body` 允许纵向滚动。
- 分配用户弹框固定为 `80dvh`，高度不随结果数量变化；低于 600px 的矮屏使用 `100dvh - 48px`。此类列表弹框由表体承担纵向滚动，弹框正文不再滚动，标题、搜索、表头、分页及底部操作保持固定。
- Modal 打开时页面滚动必须锁定，不能通过滚动浏览器寻找表单底部按钮。
- Drawer 使用视口高度，标题和操作区固定，只有 `.ant-drawer-body` 滚动。
- 宽浮层不得超过当前视口；移动端左右至少保留 12px 安全边距。
- 下拉菜单、日期面板等二级浮层继续挂载到 `body`，避免被滚动容器裁切。
- Modal 使用视口比例并设置上限：small `min(92vw, 480px)`、medium `min(92vw, 640px)`、large `min(94vw, 960px)`、wide `min(96vw, 1120px)`；Drawer 同样使用视口比例，上限分别为 560px、960px。

## 3. 表单

- 简单表单使用单列和上置可见标签，不使用 placeholder 代替标签。
- 表单项少于 7 个可直接排列；7–15 个应按业务含义分组，更多内容应拆成步骤或独立页面。
- 普通控件高度不低于 36px；登录、关键提交场景使用 44–48px。
- 必填、格式和失败原因在对应字段附近反馈；提交期间禁止重复提交。
- 登录名和密码保留正确的 `autocomplete` 语义。

## 4. 字体、颜色与焦点

- 正文基准为 14px，正文行高不低于 1.5；页面标题 22px，弹框标题 16–17px。
- 普通文字与背景对比度不低于 4.5:1；大号文字和非文本控件不低于 3:1。
- 所有可交互元素必须具有清晰的键盘焦点，不能只依赖颜色或微弱阴影表达状态。
- 禁用、错误、成功和警告使用语义色，同时配合文字或图标，不只依赖颜色。

## 5. 验收清单

- 在 390×844、768×1024、1440×900 三种视口下检查无内容遮挡。
- 用键盘完成 Tab、Shift+Tab、Enter、Escape 操作。
- 打开最长表单，确认页面不滚动、标题和底部按钮始终可见、正文可滚动到底。
- 表格在窄屏下横向滚动，分页和主要操作保持可达。
- 修改筛选条件后分页自动回到第一页，加载失败必须展示错误状态和重试入口。
- 执行 `pnpm build` 与 `git diff --check`。
